# EEG ViT-style 预训练项目说明

## 1. 项目在做什么

这个项目实现的是一种 **面向 EEG 的 ViT-style 自监督预训练方法**。

它的核心思路是：  
先把多通道 EEG 切成很多小的 **channel-time patch token**，然后随机 mask 一部分 token，再让 Transformer 根据上下文去重构每个 token 对应的 **频段能量时间轨迹**。

简单说，这个项目不是直接拿 EEG 做分类，而是先设计一个预训练任务，让模型在没有标签的情况下，先学会 EEG 的时空结构和频谱动态，之后再把学到的表示迁移到下游任务。

---

## 2. 这个预训练任务想解决什么问题

EEG 和图像、文本不太一样。  
它是连续时间信号，而且通常是多通道同步记录的。真正有信息的，往往不是某个单独采样点，而是：

- 某个通道在一小段时间内的波形模式
- 不同通道之间的协同变化
- 不同频段能量如何随时间变化

如果预训练目标设计得太简单，比如只重构原始波形、或者只预测一个 token 的平均 bandpower，模型很容易学到比较表面的模式，但不一定能学到稳定、可迁移的 EEG 表示。

这个项目要解决的就是这个问题：

第一，希望 token 化方式更合理。  
不是把整段多通道 EEG 粗暴拼成一个大 token，而是像 ViT 那样，把 EEG 切成更细粒度的 patch。这里一个 token 对应的是：

**某一个通道上的一小段时间序列。**

第二，希望预训练目标更有约束性。  
不是只预测“这一段 alpha 强不强”，而是预测：

**这一段里，不同频段的能量如何随时间变化。**

第三，希望模型能同时学习三类信息：

- 时间上下文关系
- 通道间关系
- 频段动态结构

---

## 3. 整体设计思路

整个方法可以概括成一句话：

**把 EEG 按通道和时间切成 patch token，在 token 级别做 mask，然后让 Transformer 重构每个 token 对应的时频轨迹目标。**

具体流程如下：

首先，原始 EEG 会被预处理成统一的 64 通道格式，并统一采样率。这样不同数据集的样本都能进入同一个模型。

然后，每个通道的时间序列会被切成固定长度的 patch。比如一个样本是 `64 × 1024`，如果每 128 个采样点切一个 patch，那么每个通道会得到 8 个 patch。这样整个样本会变成：

`64 × 8 = 512` 个 token

每个 token 的长度是 128。

接着，把这些 token 输入 Transformer。训练时，随机 mask 一部分 token，让模型只能看见剩下的 token，再去预测所有 token 的时频目标。

这里的目标不是原始波形，而是每个 token 对应的 **频段能量轨迹**。也就是说，模型要预测：

- 这个 token 属于哪个通道
- 这个 token 对应的时间段里
- delta、theta、alpha、beta、gamma_low 这些频段
- 在 token 内部多个时间点上的能量变化

这样模型被迫学习 EEG 更有意义的结构，而不是只记住一些简单波形。

---

## 4. 为什么采用 ViT-style tokenization

这一版和之前最大的区别是 token 的定义变了。

旧思路里，一个 token 往往是一整段时间窗内所有通道拼起来的大向量。这样做虽然简单，但每个 token 太大，而且 token 数量太少，不太像 ViT。

现在的做法更接近图像里的 patch：

- 图像里，一个 token 是一个局部图像块
- 这里，一个 token 是一个 **局部 EEG patch**

也就是：

**一个通道上的一小段时间序列 = 一个 token**

这样有几个好处：

第一，token 更细粒度。  
模型看到的不再是整段拼接后的大块输入，而是很多小 patch，更适合做 mask 建模。

第二，token 数量更多。  
这样 Transformer 可以学习更丰富的 token 间关系，而不只是处理很短的时间序列。

第三，形式上更接近 ViT。  
后续如果你要加更复杂的设计，比如 2D attention、channel embedding、hierarchical encoder，都更容易扩展。

---

## 5. 为什么目标不是原始波形，而是时频轨迹

EEG 的信息很多时候不是直接体现在波形点值上，而是体现在频谱结构上。

比如某段 EEG 的 alpha 是否增强、theta 是否变强、beta 是否波动，这些现象往往比“第 57 个采样点数值是多少”更有意义。

所以这个项目没有让模型直接重构原始信号，而是让模型去重构每个 token 的频段能量轨迹。

这个目标比“平均 bandpower”更强，因为它不是只给每个频段一个平均值，而是保留 token 内部的时间变化。

举个例子：

如果一个 token 长度对应 1.28 秒，并且目标时间分辨率是 0.16 秒，那么每个频段会有 8 个时间点的目标值。  
于是模型不是只预测：

“这一段 alpha 平均有多强”

而是要预测：

“这一段 alpha 在 8 个时间点上怎么变化”

这能更好地逼迫模型学习 EEG 的动态频谱结构。

---

## 6. 项目整体流程

从原始数据到训练，整个流程可以分成五步。

第一步，预处理原始 EEG。  
包括通道名统一、映射到固定 64 通道模板、平均参考、重采样。

第二步，切成 ViT-style token。  
每个通道沿时间轴切 patch，然后把通道维和 patch 维展开，形成 token 序列。

第三步，生成时频轨迹目标。  
对整段 EEG 先做连续时频分析，再把每个 channel-time patch 对应到频段能量轨迹。

第四步，随机 mask token。  
在 token 序列上随机选一部分 token 置零，作为被遮挡输入。

第五步，Transformer 重构目标。  
模型根据未被 mask 的 token，上下文建模后，输出每个 token 的频段轨迹预测，并与真实目标计算 loss。

---

## 7. 一个具体例子

假设现在有一个 batch，形状是：

`[8, 64, 1024]`

这表示：

- batch size = 8
- 每个样本 64 个通道
- 每个通道长度 1024

如果设置每个 patch 长度是 128，步长也是 128，那么每个通道会被切成：

`1024 / 128 = 8` 个 patch

于是每个样本会得到：

`64 × 8 = 512` 个 token

每个 token 长度是 128，所以模型输入就是：

`[8, 512, 128]`

如果频段数是 5，每个 token 内部要预测 8 个时间点，那么模型输出就是：

`[8, 512, 5, 8]`

这表示对于每个 token，模型都要输出：

- 5 个频段
- 每个频段 8 个时间点的能量变化

## 8. 项目结构总览

整个项目文件不算多，但每个文件职责很明确。  
建议按模块理解，而不是一上来陷进某个函数细节里。

---

## 9. `configs.py`：集中管理所有配置

这个文件负责保存实验配置，包括数据参数、mask 参数、模型参数和训练参数。

你可以在这里看到：

- 统一采样率是多少
- 使用多少个通道
- 每个样本有多长
- token 的 patch 长度是多少
- patch 步长是多少
- target 的时间分辨率是多少
- 频段怎么定义
- Transformer 多大
- mask 比例是多少
- 学习率和 batch size 是多少

如果你想改实验设置，通常第一步就是看这个文件。

---

## 10. `channel_config.py`：定义标准 64 通道模板

这个文件的作用是统一不同数据集的通道格式。

不同 EEG 数据来源，通道顺序、命名方式、甚至是否缺某些通道都可能不同。  
这个文件定义了项目内部统一使用的 64 通道模板，以及一些常见别名映射。

它的目的很简单：

**不管原始数据来自哪里，进入模型之前都要被整理成同一种通道格式。**

这一步是多数据集 EEG 训练里非常关键的基础工作。

---

## 11. `preprocessing.py`：原始 EEG 预处理

这个文件负责把原始 EEG 变成模型能接收的统一输入。

主要包括以下几件事：

先统一通道名，解决不同数据集写法不一样的问题。  
再把已有通道映射到标准 64 通道模板。缺失通道会补 0。  
然后做平均参考，但只对真实存在的通道做参考，不把补 0 的通道算进去。  
最后统一重采样率，比如全部变成 100 Hz。

这个文件最终输出两个东西：

一个是整理后的 EEG，形状是 `[64, T]`。  
另一个是 `channel_valid_mask`，表示哪些通道是真实存在的，哪些是缺失后补 0 的。

后者在 loss 里很重要，因为缺失通道不应该参与训练监督。

---

## 12. `targets.py`：生成 token 和时频轨迹目标

这个文件是整个预训练任务里最关键的模块之一。

它做两件事。

第一件事，是把 `[C, T]` 的 EEG 切成 channel-time patch：

`[C, T] -> [C, N, L]`

其中：

- `C` 是通道数
- `N` 是每个通道切出的 patch 数
- `L` 是每个 patch 的长度

第二件事，是为每个 patch 生成目标。  
这里不是单独对每个 patch 做平均 bandpower，而是先对整段 EEG 做连续时频分析，得到每个通道、每个频段随时间变化的轨迹。然后再把这些连续轨迹对齐到每个 patch 的时间范围，形成 patch 对应的目标。

最终每个 patch 的目标形状是：

`[F, K]`

其中：

- `F` 是频段数
- `K` 是 patch 内部的目标时间点数

所以整个目标张量是：

`[C, N, F, K]`

后面再展平成：

`[C*N, F, K]`

和 token 一一对应。

这个文件还包含 `RunningTargetNormalizer`，用于统计训练集 target 的均值和方差，以便后续标准化训练目标。

---

## 13. `dataset.py`：把样本整理成训练用输入

这个文件定义了数据集类，负责把单个样本变成模型可直接使用的输入。

它在读取一个样本时，会依次完成：

- 调用预处理函数，把原始 EEG 统一成 `[64, T]`
- 调用 target 生成函数，得到 `[C, N, L]` 的 patch 和 `[C, N, F, K]` 的目标
- 把 patch 展平成 `[C*N, L]`
- 把目标展平成 `[C*N, F, K]`

同时，它还会返回几个很重要的辅助信息：

一个是 `token_channel_indices`，告诉你每个 token 属于哪个通道。  
一个是 `token_time_indices`，告诉你每个 token 是该通道上的第几个时间 patch。  
一个是 `token_valid_mask`，表示这个 token 是否来自真实存在的通道。

这些信息在位置编码和 loss 里都会用到。

这个文件还提供了 `collate_fn`，用于把多个样本拼成 batch。  
以及 `build_mock_samples`，可以快速生成模拟 EEG 数据做调试。

---

## 14. `masking.py`：在 token 序列上做 mask

这个文件负责生成 mask，并把输入 token 中被选中的位置置零。

mask 是在 token 序列维度上进行的。  
也就是说，如果输入是：

`[B, S, L]`

那么 mask 的形状就是：

`[B, S]`

其中：

- `B` 是 batch size
- `S` 是 token 数量
- `L` 是每个 token 的长度

当前使用的是 block mask，也就是连续选一段 token 做 mask，而不是完全独立随机采样。

需要注意的是：

**mask 只作用于输入，不限制 loss 计算范围。**

模型虽然看不到被遮挡 token 的原始输入，但训练时仍然需要对所有 token 输出预测，并在所有有效 token 上计算 loss。

---

## 15. `model.py`：ViT-style EEG 预训练模型

这个文件定义了整个 Transformer 模型。

模型输入是：

`[B, S, L]`

其中每个 token 是一个 channel-time patch。

第一步，`PatchTokenizer` 会把长度为 `L` 的原始 patch 映射到 `d_model` 维的 token embedding。

第二步，加入位置信息。  
这里不是简单的一维序列位置编码，而是分别使用：

- channel embedding
- time embedding

然后相加。

这样模型就能明确知道：

- 这个 token 来自哪个 EEG 通道
- 这个 token 是第几个时间 patch

第三步，把带位置信息的 token 序列送入 Transformer Encoder，学习 token 之间的上下文关系。

第四步，通过输出头，为每个 token 预测：

`[F, K]`

也就是每个频段在 patch 内多个时间点上的能量轨迹。

所以最终模型输出形状是：

`[B, S, F, K]`

---

## 16. `losses.py`：频段均衡的 token 重构损失

这个文件定义训练使用的 loss。

当前 loss 的设计有三个重点。

第一，只在有效 token 上计算 loss。  
如果某个 token 来自原始缺失通道，那么它不会参与监督。

第二，loss 是对所有 token 计算，而不只是对被 mask 的 token。  
也就是说，模型必须学会整体重构，而不是只做局部补洞。

第三，loss 是按频段分别计算，再等权平均。  
这样可以避免低频段因为能量普遍较大，而在训练中主导整体 loss。

最终的目标是让每个频段都被公平关注，提高学习到的表示质量。

---

## 17. `trainer.py`：训练和验证过程

这个文件把数据、mask、模型和 loss 串起来，形成完整的训练流程。

训练一个 batch 时，大致过程如下：

先取出 token 输入、目标、token 所属通道索引、时间索引和有效 mask。  
然后在 token 维度上生成 mask，把一部分 token 输入置零。  
再根据 token 对应的通道，取出该通道在各频段上的标准化均值和方差，对目标做标准化。  
之后把 masked token 和索引信息送入模型前向传播。  
最后计算 loss，做反向传播和参数更新。

验证过程和训练过程类似，只是不做梯度更新。

这个文件是你以后想加训练技巧时最常改的地方，比如：

- mixed precision
- gradient clipping
- lr scheduler
- 可视化重构结果

通常都从这里加。

## 18. `train.py`：项目入口

这个文件是整个工程的启动入口。

运行它以后，会依次完成：

- 读取配置
- 设置随机种子
- 计算 patch 数量和 token 数量
- 构造数据集
- 划分训练集和验证集
- 拟合 target normalizer
- 构建 DataLoader

- 进入训练循环
- 保存验证集最优模型

如果你第一次看这个项目，建议先从 `train.py` 看起。  
它最能帮助你理解整个流程是怎么串起来的。

## 20. 输入输出形状总结

这是理解整个项目最重要的一部分。

假设一个 batch 的原始 EEG 是：

`[8, 64, 1024]`

如果 patch 长度是 128，步长也是 128，那么每个通道切成 8 个 patch。  
于是每个样本总 token 数是：

`64 × 8 = 512`

整理成模型输入后，形状是：

`[8, 512, 128]`

这表示：

- 8 个样本
- 每个样本 512 个 token
- 每个 token 长度 128

如果频段数是 5，每个 token 目标时间点数是 8，那么模型输出是：

`[8, 512, 5, 8]`

也就是：

- 每个 token
- 预测 5 个频段
- 每个频段 8 个时间点的能量轨迹

## 21. 这个预训练任务到底在逼模型学什么

可以把它理解成三个层面的学习。

第一层，是时间上下文。  
因为部分 token 被 mask，模型必须根据前后时间 patch 来推断当前 patch 的频段结构。

第二层，是空间上下文。  
因为 token 来自不同通道，模型在推断某个通道的 patch 时，也可以借助其他通道的信息。

第三层，是时频动态。  
模型要预测的不是简单的平均功率，而是频段能量随时间的变化轨迹，所以它必须学会 EEG 的动态频谱结构。

这三层能力合在一起，才是这个预训练任务真正希望模型获得的表示能力。

---

## 22. 为什么这种设计适合 EEG

因为 EEG 同时具有三种结构：

- 时间结构
- 通道结构
- 频谱结构

这个项目正好分别对应了这三点：

- patch tokenization 负责切出局部时间结构
- Transformer 负责学习跨 token 的时空关系
- 时频轨迹目标负责约束频谱动态结构

所以它不是随便给 EEG 套一个 Transformer，而是尽量让输入形式、预训练目标和 EEG 自身特性对齐。

## 23. 推荐的新手阅读顺序

如果你是第一次接触这个项目，推荐按下面顺序看代码：

先看 `train.py`，理解程序主流程。  
再看 `configs.py`，知道关键参数分别控制什么。  
然后看 `dataset.py`，弄清楚一个样本怎么变成 token 和 target。  
接着重点看 `targets.py`，理解预训练目标是怎么构造出来的。  
再看 `model.py`，理解 token 是怎么编码并送进 Transformer 的。  
最后看 `losses.py` 和 `trainer.py`，理解训练如何完成。

如果你先抓住下面这三件事，整个项目就会非常清楚：

第一，token 是怎么从多通道 EEG 切出来的。  
第二，模型到底预测什么目标。  
第三，loss 是怎么避免无效通道和低频主导问题的。

这个项目做的是：

**把多通道 EEG 切成 ViT-style 的 channel-time patch token，在 token 级别做 mask，让 Transformer 去重构每个 token 对应的频段能量时间轨迹，从而学习可迁移的 EEG 表示。**
