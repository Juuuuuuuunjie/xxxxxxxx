# EEG 时频轨迹重构预训练项目说明

## 1. 这个预训练任务想解决什么问题

EEG 预训练和图像、文本不太一样。图像里遮一块，模型去补像素，任务通常比较直观；文本里遮几个词，模型去预测词语，也比较自然。但 EEG 是连续时间信号，它真正有意义的信息往往不是某个瞬时采样点本身，而是**不同频段的活动模式如何随时间变化**。如果预训练目标设计得太简单，模型很容易学到一些表面模式，却没有真正学到稳定、可迁移的脑电表示。

这个项目就是为了解决这个问题。我们不希望模型只是“看见一段 EEG，输出一个粗糙的平均频段能量”，因为那样的任务太简单。真正希望模型学到的是：**在一个时间片段内部，delta、theta、alpha、beta 等频段的能量是怎么随着时间变化的**。这种变化轨迹比单个平均值更接近 EEG 的真实动态结构，也更有可能对后续分类、检测、跨数据集迁移等任务有帮助。

另一个实际问题是，不同 EEG 数据集之间差异很大。通道数量可能不同，通道命名方式可能不同，采样率可能不同，有些数据集缺少某些通道，参考方式也可能不一样。如果不先把这些问题统一起来，预训练模型很难在多个来源的数据上稳定工作。所以这个项目除了设计预训练目标，还做了一层非常重要的事情：**把不同数据集的 EEG 统一整理成同一种输入格式**。

---

## 2. 整个设计思路是什么

这个项目采用的是“**输入时域 EEG，重构时频轨迹目标**”的思路。

具体来说，模型输入的是一段多通道 EEG 的时域片段。训练时，我们会随机把一部分时间 token 做 mask，也就是把这些 token 的输入置零，让模型不能直接看到完整原始信号。然后让模型根据上下文，去预测整段 EEG 对应的时频特征。

这里最关键的一点是：模型输出的不是每个 token 的一个平均频段能量，而是**每个 token 内部、每个通道、每个频段的一条能量变化轨迹**。也就是说，模型不仅要知道“这一秒 alpha 大概强不强”，还要知道“这一秒内部 alpha 是怎么变化的”。这样预训练任务就比简单的 bandpower 重构更严格，也更接近 EEG 分析中真正重要的动态过程。

loss 的设计也围绕这个目标展开。我们不是只在被 mask 的区域上算 loss，而是对**整个片段**都算 loss。原因很直接：如果只对 mask 区域算 loss，模型可能只学会“补洞”，但对那些原本没有被遮挡的正常片段反而重构得很差。现在这个版本要求模型对整个片段都输出合理的结果，这样会逼着模型学习更稳定的整体表征。

另外，不同频段的能量尺度差异很大，低频通常比高频能量大得多。如果直接把所有频段混在一起做 MSE，训练往往会被低频主导。因此这里的 loss 是**按频段分别计算，再对各频段等权平均**。这样做可以尽量避免模型只顾着拟合 delta/theta，而忽略 alpha、beta、gamma 的结构。

---

## 3. 这个项目的整体框架

整个项目可以分成四个部分：数据统一、目标生成、模型重构、训练优化。

第一部分是数据统一。项目先把不同来源的 EEG 映射到固定的 64 通道模板上。存在的通道放到对应位置，缺失的通道补 0，同时记录哪些通道是真实存在的。然后做平均参考，并把采样率统一到 100 Hz。这样模型看到的输入格式始终一致，不会因为不同数据集通道数或采样率不同而变化。

第二部分是目标生成。EEG 信号会先按固定长度切成 token，例如每 1 秒一个 token。与此同时，代码会对整段 EEG 计算连续时频表示，再把频率维度压缩成几个常见频段，比如 delta、theta、alpha、beta、gamma_low，但会保留时间维度，所以最终每个 token 的目标不是一个标量，而是一条短时间的频段能量轨迹。

第三部分是模型重构。模型本身是一个基于 Transformer 的 encoder。输入是时域 token，经过线性投影和位置编码后送入 Transformer，让不同时间 token 之间建立上下文关系。最后通过一个输出头，把每个 token 映射成对应的 `[通道 × 频段 × token内时间帧]` 形式的时频轨迹预测。

第四部分是训练优化。训练时会随机 mask 掉一部分时间 token，但 loss 会对整段片段计算。缺失通道不参与 loss。目标在训练前会根据训练集统计均值和方差做标准化，避免频段尺度差异过大。最终模型学到的是一种：**即使只看部分 EEG 片段，也能恢复整段 EEG 时频动态结构** 的能力。

---

## 4. 一个直观例子

假设现在有一段 10 秒 EEG，采样率统一到 100 Hz，那么原始输入长度就是 1000 个采样点。

如果我们设置每个 token 长度为 1 秒，那么这段信号会被切成 10 个 token。每个 token 包含 64 个通道、每通道 100 个采样点。

旧版本里，每个 token 的目标可能只是一个 `[64, 5]` 的矩阵，也就是 64 个通道在 5 个频段上的平均能量。这很容易让任务变成“粗略估计这一秒的频段强度”。

新版本里，每个 token 的目标变成 `[64, 5, K]`。如果 `K=10`，那就表示这一秒内部每 0.1 秒都有一个频段能量值。于是模型真正需要预测的是：**这一秒内部每个通道、每个频段的能量曲线**。这就比只预测一个平均值更难，也更符合“时频动态建模”的目标。

---

## 5. 预训练任务到底在学什么

从直觉上看，这个任务希望模型学会三件事。

第一，学会时间上下文关系。因为输入有些 token 被 mask 掉，模型必须利用前后的 EEG 信息去推断当前这段时频结构。

第二，学会多通道之间的关联。EEG 不是各通道独立变化的，不同脑区活动在很多情况下是有关联的。模型在重构一个通道的时频轨迹时，也会从其他通道获得帮助。

第三，学会频段动态结构。我们关心的不只是“哪个频段强”，还关心“这个频段何时增强、何时减弱、变化速度如何”。这正是时频轨迹目标相对于平均 bandpower 目标更重要的地方。

---

## 6. 项目的代码结构

这个项目的代码量不大，但每个文件都有明确分工。只要按顺序看，整体逻辑是比较容易跟上的。

---

## 7. `configs.py`：统一管理实验配置

这个文件专门负责保存所有超参数和配置。包括数据处理参数、mask 参数、模型结构参数和训练参数。

在数据配置里，最重要的是采样率、固定通道数、clip 长度、token 长度、token 步长，以及时频目标的时间分辨率。比如你可以通过 `window_seconds` 控制每个 token 的长度，通过 `target_frame_seconds` 控制每个 token 内部要重构多少个时间点的频段轨迹。

在 mask 配置里，主要是控制 mask 比例和 block mask 的长度范围。

在模型配置里，主要是 Transformer 的宽度、层数、头数等结构参数。

在训练配置里，主要是 batch size、epoch 数、学习率、保存路径等。

可以把这个文件理解成项目的“总开关”。如果想改实验设置，通常先看这里。

---

## 8. `channel_config.py`：定义固定 64 通道模板

这个文件解决的是不同数据集通道不一致的问题。

项目内部使用一个固定的 64 通道顺序作为标准模板。任何输入 EEG 都会被映射到这个模板上。这样模型永远接收到同一种通道排列，不需要关心原始数据来自哪个数据集。

这个文件里还会定义一些通道名别名映射，例如有的数据集写 `T3`，有的数据集写 `T7`，代码会在这里统一处理。这一步虽然看起来基础，但对于多数据源 EEG 项目非常重要，因为很多问题都出在通道命名不统一上。

---

## 9. `preprocessing.py`：把原始 EEG 变成统一格式

这个文件负责预处理原始 EEG。

第一步是整理通道名，把各种不同写法统一成标准写法。

第二步是把输入通道映射到固定 64 通道模板。如果某个通道存在，就放到相应位置；如果不存在，就补 0。

第三步是做平均参考。这里特别注意，平均参考只会使用真实存在的通道，不会把那些缺失后补 0 的通道算进去。

第四步是重采样，把不同数据的采样率统一到 100 Hz。

最终输出的是一个固定 shape 的 EEG 张量，以及一个 `channel_valid_mask`，用来表示哪些通道是真实存在的，哪些是缺失后补 0 的。

---

## 10. `targets.py`：生成预训练要重构的时频轨迹目标

这个文件是当前版本里最核心的部分之一，因为它决定了预训练任务到底在学什么。

首先，代码会把 EEG 按固定窗口切成时间 token，供模型作为输入。

然后，它不会只在每个 token 内单独算一个平均 bandpower，而是对整段 EEG 做连续时频分析。得到频谱以后，再把频率维度按预先定义好的几个频段做平均，比如 delta、theta、alpha、beta、gamma_low。这样就把完整频谱压缩成更紧凑、更稳定的频段表示。

但这里不会把时间信息平均掉。相反，会保留时频图中的时间轴，然后再把这些连续的频段能量轨迹对齐到每个 token。于是每个 token 最终得到的目标是一个三维结构：通道、频段、token 内时间帧。

这个文件里还有一个 `RunningTargetNormalizer`，它的作用是统计训练集目标的均值和方差。因为不同通道、不同频段的值域不一样，如果不先标准化，训练时很容易被大尺度频段主导。这个 normalizer 的设计是保留时间变化，但按通道和频段做统计，这样比较适合当前这种时频轨迹目标。

---

## 11. `dataset.py`：组织成模型可直接读取的数据集

这个文件定义了预训练数据集类。

它接收的原始样本通常是一个字典，里面至少包含三样东西：原始信号、通道名列表、原始采样率。

当 `Dataset` 取一个样本时，会自动调用预处理，把原始 EEG 变成统一的 64 通道格式；然后调用目标生成函数，得到输入 token 和对应的时频轨迹目标；最后把这些内容整理成 PyTorch 训练可直接使用的张量。

这个文件还定义了 `collate_fn`，负责把多个样本拼成一个 batch。

此外还有一个 `build_mock_samples`，它可以生成带有一些简单节律变化的模拟 EEG，用来快速测试整个训练流程是否跑通。对于刚接触这个项目的人来说，这个函数很有用，因为即使没有真实 EEG 数据，也能先验证代码整体是否工作正常。

---

## 12. `masking.py`：生成输入 mask

这个文件很简单，但它决定了训练时模型如何被“遮挡输入”。

当前版本使用的是时间 block mask。也就是说，不是随机遮掉离散点，而是随机选择若干个连续时间 token，把它们的输入置零。这样更符合 EEG 连续信号的特点。

这里要特别强调：mask 只影响输入，不影响 loss 的计算范围。模型虽然看不到某些 token 的原始输入，但最终还是要对整个片段输出完整预测，并且整段都参与 loss。

---

## 13. `model.py`：定义预训练模型

这个文件定义的是一个比较标准的时序 Transformer 重构模型。

第一部分是 token 投影层。原始输入 token 本质上是一个 64 通道时域窗口，被展平成一个长向量。模型先通过线性层把它映射到 Transformer 使用的隐藏维度。

第二部分是位置编码。因为 Transformer 本身不知道 token 顺序，所以需要给每个时间 token 加上位置信息。

第三部分是 Transformer Encoder。这里负责建模不同时间 token 之间的关系，让模型能够利用上下文恢复被遮挡片段，同时也学习整段信号的时序结构。

最后一部分是输出头。它会把每个 token 的隐藏表示映射成 `[通道 × 频段 × token内时间帧]` 的预测结果。也就是说，模型输出的不是一个简单分类分数，也不是单个平均 bandpower，而是一段完整的时频轨迹重构结果。

---

## 14. `losses.py`：定义更合理的重构损失

这个文件负责计算训练 loss。

当前版本的 loss 设计有两个关键原则。

第一个原则是，loss 对整个片段计算，而不只是对被 mask 的 token 计算。这样模型不会只顾着补被遮挡区域，而忽略正常可见区域的重构质量。

第二个原则是，loss 按频段分别统计，然后再做等权平均。这样每个频段都会对总 loss 有相近的重要性，避免低频因为能量更大而主导训练。

另外，loss 里还会使用 `channel_valid_mask`，把那些原始数据中缺失、后续补 0 的通道排除掉，避免模型被迫去拟合并不存在的 EEG 通道。

---

## 15. `trainer.py`：实现训练和验证循环

这个文件负责把前面的各个模块真正串起来。

训练一个 batch 时，代码会先读取输入 token、时频轨迹目标和通道有效掩码。然后生成当前 batch 的时间 mask，把一部分 token 输入置零。接着会对 target 做标准化，再送入模型前向传播，最后计算完整片段的重构 loss，并做反向传播和参数更新。

验证过程和训练过程基本一致，只是不会更新参数。

这个文件可以理解成“训练过程的总执行器”。如果以后你想加入更复杂的策略，比如可视化中间结果、混合精度训练、梯度裁剪等，通常都需要从这里入手。

---

## 16. `train.py`：整个项目的启动入口

这个文件是主程序入口。

运行它以后，代码会先读取配置、设置随机种子，然后构造 mock 数据或你自己的真实数据，接着建立数据集和 DataLoader，再统计训练集 target 的均值方差，初始化模型、优化器和 loss，最后进入 epoch 循环开始训练。

训练过程中，它会输出训练 loss 和验证 loss，并保存验证集表现最好的模型参数。

如果你是第一次接触这个项目，最推荐先看这个文件。因为它最能帮助你理解：整个工程是怎么从数据、到模型、到 loss、再到训练串起来的。

---

## 17. `utils.py`：一些通用工具函数

这个文件主要放一些辅助函数，比如设置随机种子、在保存模型时自动创建目录等。

它不是项目的核心逻辑，但可以让代码更整洁，也更方便复现实验。

---

## 18. 这套代码的输入输出是什么样的

从模型角度看，输入是一个 batch 的 EEG token 序列。每个 token 是一个固定时间窗内的 64 通道时域信号，展平成一维向量后送入模型。

输出则是对应的时频轨迹张量。对于每个 token，模型都要预测所有通道、所有频段、所有 token 内时间帧上的能量值。

如果用更直白的话说，模型输入的是“EEG 的时间波形片段”，输出的是“这些片段对应的频段能量随时间变化的曲线”。

这也是这个项目和简单 bandpower 重构最大的区别。

---

## 19. 为什么这个版本比简单 bandpower 重构更合理

如果每个 token 只预测一个平均频段能量，模型只需要回答“这一秒 alpha 强不强”，任务其实比较粗糙。模型可能学会了大致判断节律强弱，但未必真正理解这一秒内部的动态结构。

现在的版本要求模型预测 token 内部多个时间点的频段轨迹。这样模型必须学会：一个频段是在这一秒开头增强、中间减弱，还是后半段突然上升。这种信息对于很多 EEG 场景更重要，也更贴近真实神经动态。

同时，通过按频段均衡 loss，训练不会被低频完全带着走。这样最终得到的表示更有机会兼顾多个频段，而不是只学会拟合最强的那部分信号。

---

## 20. 新人建议怎么阅读代码

如果你是第一次看这个项目，最好的顺序不是从某个细节函数开始钻，而是先把整体流程建立起来。

建议先看 `train.py`，知道整个程序怎么启动。接着看 `configs.py`，了解所有关键参数。然后看 `dataset.py`，弄清楚原始 EEG 是怎么被组织成模型输入和目标的。之后重点看 `preprocessing.py` 和 `targets.py`，因为它们决定了数据统一方式和预训练任务本身。最后再看 `model.py`、`losses.py` 和 `trainer.py`，就能把完整逻辑串起来。

如果能先理解下面这三件事，整个项目就基本掌握了：

第一，为什么要把不同数据集统一成固定 64 通道输入。  
第二，为什么预训练目标从平均 bandpower 改成了频段能量时间轨迹。  
第三，为什么 loss 要对整段片段计算，而且要按频段均衡。

理解这三点后，再回头看每个代码文件，就会清晰很多。

---

## 21. 一句话总结这个项目

这个项目做的是：**把不同来源的 EEG 统一成固定格式，随机遮挡部分时域输入，让 Transformer 去重构整段 EEG 在多个频段上的时间变化轨迹，从而学习更稳定、更有迁移能力的 EEG 表示。**
